# Contributing

Thanks for taking the time. This is a small, single-purpose app — three source
files and a test suite — so most changes are quick to make and quick to review.

## The toolchain is version-pinned, and it matters

The Freshworks CLI refuses to run on anything but the Node version it was built
for, and there is a **separate CLI build per Node major**. The pairing this app
is developed against is declared in `manifest.json`:

```json
"engines": { "node": "24.11.1", "fdk": "10.1.9" }
```

```bash
nvm install 24.11.1 && nvm use 24.11.1
npm install https://cdn.freshdev.io/fdk/latest-v24.tgz -g
fdk version     # should report 10.1.9
```

If you install the plain `latest.tgz` you will get the Node 18 build, and it
will refuse to run. If you upgrade Node, update `engines` in the same pull
request.

## Getting it running locally

You do not need a Vobiz account to develop the panel.

```bash
npm install
npm run mock-backend     # terminal 1 — http://localhost:8092
fdk run                  # terminal 2 — http://localhost:10001
```

Then open a Freshdesk page with `?dev=true` appended, and set the app's
installation parameters at <http://localhost:10001/custom_configs>:

| Setting | Value |
| --- | --- |
| Calling backend URL | `http://localhost:8092` |
| Agent identity | anything, e.g. `priya` |
| SIP registrar URL | leave blank |

The mock backend accepts any Auth ID and Auth Token. Use the literal `fail` as
the Auth ID to exercise the login error path. See
[mock-backend/README.md](mock-backend/README.md).

> The mock serves placeholder SIP credentials, so registration fails and the
> Call button stays disabled — that is the panel working correctly. To exercise
> real audio, export `VOBIZ_SIP_USER` and `VOBIZ_SIP_PASSWORD` from a real Vobiz
> SIP endpoint before starting the mock.

## Before you open a pull request

```bash
npm test          # 45 tests, coverage must stay at or above 80% everywhere
fdk validate      # must report 0 platform errors and 0 lint errors
fdk pack          # must succeed
```

CI runs all three plus a scan for credentials and real phone numbers.

### The coverage gate is real

Freshworks requires **80% on lines, statements, functions, and branches** for
Marketplace submission, and `fdk pack` enforces it. CI fails below that. If you
add a code path, add a test for it.

`fdk pack` also wants *local simulation* coverage, which is only generated by
running the app inside a real Freshdesk account via `?dev=true`. Locally you can
use `fdk pack --skip-coverage`; do not use that flag for a Marketplace build.

## How the tests work

`tests/harness.js` loads the real `app/scripts/app.js` and the real markup from
`app/index.html` into jsdom, with fakes for the Freshworks SDK, JsSIP, and
`fetch`. Tests therefore exercise the code that ships, including its DOM wiring,
rather than an extracted copy.

When you fix a bug, add a test that fails without the fix and say so in a
comment — several existing tests are written that way, and they are the ones
that stop a regression coming back.

## House style

- No build step, no framework, no bundler. Plain ES modules-free browser JS.
- No dependencies in the app itself. JsSIP loads from a pinned jsDelivr URL.
- Comments explain *why*, not *what* — particularly around the SIP call order
  and the `peerconnection` binding, both of which look wrong until you know the
  failure they prevent.
- User-facing strings are sentences, and say what to do next.

## Things that will be sent back

- Credentials, SIP passwords, production hostnames, or real phone numbers in the
  diff. CI catches most of these; please do not rely on it.
- Storing anything sensitive in `localStorage`, `sessionStorage`, or cookies.
  Freshworks rejects apps that do, and so will we.
- Loading anything that touches the Freshworks SDK from a CDN. Third-party
  libraries that do not touch it — JsSIP, for instance — may be CDN-loaded over
  HTTPS from jsDelivr or cdnjs. Not unpkg; `fdk validate` errors on it.
- Changing the backend contract without updating both
  `docs/backend-contract.md` and `mock-backend/server.js`.
